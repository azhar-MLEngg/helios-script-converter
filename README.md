# Snowflake to StarRocks Conversion System

An AI-powered conversion system that transforms Snowflake Python scripts to StarRocks-compatible format using Claude Agent SDK.

## Features

- **AI Layer 1**: Connection Converter Agent - Converts Snowflake connections to StarRocks using Claude
- **Deterministic Layer**: Query Converter - Rule-based SQL transformations
- **AI Layer 2**: Debugging Agent - Iteratively fixes validation errors using Claude
- **Validation**: Automated testing of converted scripts
- **CLI Interface**: Easy-to-use command-line tool

## Architecture

```
Input Script → Connection Converter (AI) + Query Converter (Rules) 
           → Assembly → Validation → Debugging (AI) → Output
```

See [AGENTS.md](AGENTS.md) for detailed architecture documentation.

## Installation

### Prerequisites

- Python 3.10 or higher
- StarRocks database instance (for validation)
- Anthropic API key

### Setup

1. Clone the repository:
```bash
git clone <repository-url>
cd script-converter
```

2. Create virtual environment:
```bash
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
```

3. Install dependencies:
```bash
pip install -r requirements.txt
```

4. Configure environment:
```bash
cp .env.example .env
# Edit .env and add your ANTHROPIC_API_KEY and StarRocks connection details
```

5. Review and customize `config.yaml` if needed.

## Usage

### Convert a Script

```bash
python main.py convert input_script.py -o output_script.py
```

Options:
- `-o, --output`: Output file path (default: `<input>.converted.py`)
- `-c, --config`: Path to custom config.yaml
- `-v, --verbose`: Enable verbose logging
- `--no-validate`: Skip validation step

### Validate StarRocks Connection

```bash
python main.py validate-connection
```

### Convert a Single Query

```bash
python main.py convert-query "SELECT * FROM table WHERE id = 1"
```

Customize agent behavior, conversion rules, and logging settings. See `config.yaml` for all options.

### Conversion Rules (`rules/conversion_rules.yaml`)

Define custom data type mappings, function conversions, and syntax transformations.

## Examples

### Example 1: Basic Conversion

**Input (Snowflake):**
```python
import snowflake.connector

conn = snowflake.connector.connect(
    user='myuser',
    password='mypass',
    account='myaccount',
    warehouse='mywarehouse',
    database='mydb',
    schema='myschema'
)

query = """
SELECT id, name::VARCHAR, created_at::TIMESTAMP_NTZ
FROM users
WHERE status = 'active'
"""

cursor = conn.cursor()
cursor.execute(query)
results = cursor.fetchall()
```

**Output (StarRocks):**
```python
# Converted from Snowflake to StarRocks
# Generated by Snowflake-to-StarRocks Conversion System
# Please review and test before production use

import pymysql

conn = pymysql.connect(
    host='localhost',
    port=9030,
    user='myuser',
    password='mypass',
    database='mydb'
)

query = """
SELECT id,
       CAST(name AS VARCHAR),
       CAST(created_at AS DATETIME)
FROM users
WHERE status = 'active'
"""

cursor = conn.cursor()
cursor.execute(query)
results = cursor.fetchall()
```

### Example 2: Complex Query with Functions

**Input:**
```sql
SELECT 
    user_id,
    PARSE_JSON(metadata):name::VARCHAR as name,
    DATEADD(day, 7, created_at) as week_later,
    IFF(status = 'active', 1, 0) as is_active
FROM users
```

**Output:**
```sql
SELECT user_id,
       CAST(JSON_EXTRACT(PARSE_JSON(metadata), '$.name') AS VARCHAR) AS name,
       DATE_ADD(created_at, INTERVAL 7 DAY) AS week_later,
       IF(status = 'active', 1, 0) AS is_active
FROM users
```

## Conversion Rules

### Data Type Mappings

| Snowflake | StarRocks |
|-----------|-----------|
| VARIANT | JSON |
| TIMESTAMP_NTZ/LTZ/TZ | DATETIME |
| NUMBER(38,0) | BIGINT |
| ARRAY | ARRAY<JSON> |

### Function Mappings

| Snowflake | StarRocks |
|-----------|-----------|
| FLATTEN() | UNNEST() |
| GET_PATH() | JSON_EXTRACT() |
| TO_TIMESTAMP() | STR_TO_DATE() |
| DATEADD() | DATE_ADD() |
| IFF() | IF() |
| LISTAGG() | GROUP_CONCAT() |

### Syntax Transformations

- `::` casting → `CAST(... AS ...)`
- `||` concatenation → `CONCAT()`
- `$1, $2` positional params → Named columns
- `QUALIFY` clause → Subquery with `ROW_NUMBER()`

## Troubleshooting

### Connection Errors

If you get connection errors:
1. Verify StarRocks is running: `mysql -h localhost -P 9030 -u root`
2. Check `.env` configuration
3. Run: `python main.py validate-connection`

### API Errors

If you get Anthropic API errors:
1. Verify `ANTHROPIC_API_KEY` is set correctly
2. Check API quota and rate limits
3. Review logs in `logs/converter.log`

### Validation Failures

If validation fails repeatedly:
1. Review error logs: `<output>.error.log`
2. Check conversion rules in `rules/conversion_rules.yaml`
3. Run with `--no-validate` to skip validation
4. Manually review and fix the output

## Limitations

- Complex `QUALIFY` clauses may need manual review
- Nested JSON operations may require adjustments
- Snowflake-specific features (STAGE, STREAM, TASK) not supported
- Max 3 debugging iterations before manual review required
